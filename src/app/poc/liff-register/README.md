# S3 · ผูกบัญชีลูกค้าผ่าน LINE LIFF

ตอบคำถาม 5 ข้อ · query param ส่งผ่านมาไหม · ได้ ID token ไหม ·
เซิร์ฟเวอร์ยืนยันกับ LINE ได้ไหม · ใช้เวลากี่วินาที · เปิดนอกแอป LINE แล้วใช้ได้ไหม

**เกณฑ์ผ่าน** ได้ LINE userId ที่ยืนยันฝั่งเซิร์ฟเวอร์ โดยลูกค้าไม่ต้องล็อกอินซ้ำ
และทั้งกระบวนการไม่เกิน 30 วินาที

## ตั้งค่าก่อนรัน

### 1 · LINE Developers Console

1. สร้าง **Provider** (ถ้ายังไม่มี)
2. สร้าง channel แบบ **LINE Login**
3. ในแท็บ **LIFF** → **Add** และตั้งค่า
   - **Size** · Full
   - **Endpoint URL** · `https://<ngrok-url>/poc/liff-register`
   - **Scopes** · ติ๊ก **`openid`** และ `profile`
4. คัดลอก **LIFF ID** (รูปแบบ `1234567890-abcdefgh`)
5. ไปแท็บ **Basic settings** คัดลอก **Channel ID** (ตัวเลขล้วน คนละตัวกับ LIFF ID)

> ⚠️ **ถ้าไม่ติ๊ก `openid` ทั้ง POC นี้จะล้มเหลว**
> `liff.getIDToken()` จะคืนค่า `null` และเซิร์ฟเวอร์ยืนยันตัวตนไม่ได้
> หน้าจอจะแจ้งข้อความนี้ให้โดยเฉพาะ

### 2 · `.env.local`

```bash
NEXT_PUBLIC_LIFF_ID=1234567890-abcdefgh
LINE_LOGIN_CHANNEL_ID=1234567890
BILL_TOKEN_SECRET=$(openssl rand -base64 48)
```

### 3 · รัน

```bash
npm install
npm run dev
npx ngrok http 3000      # LINE ต้องเข้าถึง endpoint จากภายนอก
```

เอา URL ของ ngrok ไปใส่เป็น Endpoint URL ใน LIFF app ให้ตรงกัน

### 4 · ทดสอบ

เปิด `https://<ngrok-url>/poc/liff-register/qr` **บนคอม** แล้วสแกน QR ด้วยมือถือ

## ทำไมต้องซับซ้อนขนาดนี้

สามชั้น แต่ละชั้นกันคนละเรื่อง ถ้าขาดชั้นใดชั้นหนึ่งระบบพัง

| ชั้น | กัน |
|---|---|
| **1 · ลายเซ็นโทเคน** | เลขบิลเป็น running number เดาได้หมด · ถ้า QR มีแค่ `04832` ใครเดาถูกก็ผูกบัญชีตัวเองเข้ากับบิลคนอื่นแล้วเห็นประวัติทั้งหมด |
| **2 · ยืนยัน ID token** | `liff.getProfile().userId` มาจากฝั่ง client · เปิด devtools แล้วยิง request เองส่ง userId อะไรก็ได้ · **ต้องให้ LINE ยืนยันฝั่งเซิร์ฟเวอร์เท่านั้น** |
| **3 · เบอร์ 4 ตัวท้าย** | ใบรับของตกหล่นแล้วคนอื่นเก็บได้ |

### จุดที่พลาดกันบ่อยที่สุด

```ts
// ❌ ผิด — เชื่อค่าจากฝั่ง client
const { userId } = await liff.getProfile();
await fetch("/api/link", { body: JSON.stringify({ userId }) });

// ✅ ถูก — ส่ง token ให้เซิร์ฟเวอร์เอาไปให้ LINE ตรวจ
const idToken = liff.getIDToken();
await fetch("/api/link", { body: JSON.stringify({ idToken }) });
```

หน้า `page.tsx` **ไม่เคยส่ง userId ไปให้เซิร์ฟเวอร์เลย** โดยตั้งใจ

## กรณีร้านไม่มีเบอร์ของลูกค้า

บิล `04833` จำลองกรณีนี้ · ระบบจะ **ข้าม** การตรวจเบอร์ 4 ตัวท้าย

เหตุผล — นี่คือกลุ่ม 20% ที่ติดต่อไม่ได้ ซึ่งเป็น pain point ที่หนักที่สุด
การบังคับให้กรอกข้อมูลที่ร้านไม่เคยมี คือการปิดประตูใส่กลุ่มที่อยากดึงเข้าระบบที่สุด

แลกมาด้วยความเสี่ยง — ถ้าใบรับของของบิลกลุ่มนี้ตกหล่น คนเก็บได้ผูกบัญชีได้เลย
รับได้ เพราะสิ่งที่เห็นคือสถานะผ้าของบิลเดียว ไม่ใช่ประวัติทั้งหมด
**แต่ต้องเขียนข้อจำกัดนี้ไว้ในรายงาน ไม่ใช่ปล่อยผ่าน**

| # | ทดสอบ | คาดหวัง |
|---|---|---|
| 1 | สแกนจากกล้องในแอป LINE | เปิดใน LINE ไม่ต้องล็อกอิน |

| 6 | ทั้ง iOS และ Android | ทำงานเหมือนกัน |
| 7 | จับเวลารวม | ≤ 30 วินาที |

## ตอนขึ้น MVP 1 ต้องเปลี่ยนอะไร

- ลบ `poc-bill-store.ts` → ใช้ `modules/intake/repository.ts` และ `modules/customer/repository.ts`
- `linkLineUser()` ต้องเขียนลงฐานข้อมูลจริง พร้อมกติกาการจับคู่ (ดู ARCHITECTURE)
- เพิ่ม rate limit บน endpoint กันการยิงเดาเบอร์ 4 ตัวท้าย (10,000 ความเป็นไปได้)
- เพิ่มปุ่ม **ยกเลิกการผูกบัญชี** · PDPA
- บันทึกเมตริก **% ของบิลที่ผูก LINE ภายใน 7 วัน**

ข้อที่ 3 สำคัญกว่าที่คิด — ไม่มี rate limit แล้วเบอร์ 4 ตัวท้ายกันอะไรไม่ได้เลย
