## เปิดไฟล์ยังไง

**ง่ายที่สุด** — เปิด <https://demo.bpmn.io> แล้วลากไฟล์เข้าไปวาง แก้ไขได้ทันที ไม่ต้องติดตั้งอะไร

**แบบติดตั้ง** — Camunda Modeler (ฟรี ใช้ได้ทั้ง mac/windows) เหมาะกับการทำงานต่อเนื่อง

**ใน VS Code** — ติดตั้งส่วนขยาย *BPMN Editor* แล้วดับเบิลคลิกไฟล์ได้เลย

**ใน draw.io** — `File → Import from → Device` รองรับ `.bpmn`

**ส่งออกเป็นรูปสำหรับเอกสาร** — ใน bpmn.io หรือ Camunda Modeler กด *Download as SVG*
SVG เป็น vector จึงคมเมื่อพิมพ์ ใช้ใน Word และสไลด์ได้โดยไม่แตก

## โครงสร้างที่ใช้ และเหตุผล

### ลูกค้าเป็น Pool แยก ไม่ใช่ Lane
ตามหลัก BPMN · Pool = องค์กรหรือผู้มีส่วนร่วม · Lane = หน่วยย่อย**ภายใน** pool นั้น
ลูกค้าไม่ใช่หน่วยย่อยของร้าน จึงต้องเป็น pool ของตัวเอง
และเมื่อแยกแล้ว เส้นที่เชื่อมสอง pool ต้องเป็น **message flow (เส้นประ)** ไม่ใช่ sequence flow

### As-Is ใช้ Manual Task ทั้งหมด
ทุก task ในไฟล์ As-Is เป็น `manualTask` คือคนทำล้วน ไม่มีระบบช่วย
ส่วน To-Be แยกเป็น `userTask` (คนทำผ่านระบบ) และ `serviceTask` (ระบบทำเอง)
ความต่างนี้จึงอ่านออกจากรูปโดยไม่ต้องมีคำบรรยาย

### Data Store กับ Data Object คือหัวใจของการเปรียบเทียบ
As-Is มี data store ชื่อ **เล่มบิล (กระดาษ)** และ data object **เลขบิลบนป้ายกระดาษ**
To-Be มี data store **ฐานข้อมูลระบบ** และ data object **ป้ายบาร์โค้ดรายชิ้น**

สองบรรทัดนี้คือข้อโต้แย้งทั้งหมดของโครงงาน · แหล่งข้อมูลเดียวของธุรกิจวันนี้คือสมุดกระดาษ
และตัวตนของผ้าหนึ่งชิ้นคือหมึกบนกระดาษที่หลุดได้

### Gateway ที่เพิ่มเข้ามา
| Gateway | ทำไมต้องมี |
|---|---|
| ลูกค้าให้เบอร์โทรหรือไม่ | ~20% ของบิลไม่มีช่องทางติดต่อ ≈ 4,000 บิลต่อปี · ถ้าไม่มี gateway นี้ แผนภาพอธิบาย pain point ข้อนี้ไม่ได้เลย |
| งานด่วนหรือไม่ | 4–5 ครั้งต่อสัปดาห์ · As-Is แจ้งด้วยวาจาไม่เหลือร่องรอย · To-Be เป็น flag บนบิล |

### Task ที่เพิ่มใน As-Is
`รับข้อมูลลูกค้า` — ของเดิมไม่มี task นี้เลย ทั้งที่ pain point ที่หนักที่สุดคือติดต่อลูกค้าไม่ได้
ถ้าไม่มีขั้นตอนนี้ในแผนภาพ ก็ไม่มีจุดให้มันล้มเหลว

## สิ่งที่เปลี่ยนจาก To-Be

| As-Is | To-Be | รูปแบบการเปลี่ยน |
|---|---|---|
| คำนวณราคาจากประสบการณ์ | Service Task ดึงจากตารางราคา | Automate |
| เขียนเลขบิลบนเสื้อผ้าทุกชิ้น | Service Task พิมพ์ป้ายบาร์โค้ด | Automate |
| ไม่ให้เบอร์ = ติดต่อไม่ได้ตลอดไป | ใบรับของมี QR ให้ผูก LINE เองภายหลัง | เพิ่มเส้นทางใหม่ |
| แจ้งช่างรีดด้วยวาจา | ตั้งสถานะงานด่วน แล้วขึ้นในคิวช่างรีดเอง | Eliminate |
| เล่มบิลกระดาษ | ฐานข้อมูล + `status_event` | Informate |
| — | บันทึก `status_event = RECEIVED` | **งานใหม่ที่เพิ่มขึ้น** |

แถวสุดท้ายคือต้นทุน ไม่ใช่ประโยชน์ · ต้องเขียนไว้ในรายงานให้ชัด
ไม่ใช่ทำเหมือนระบบไม่มีต้นทุนอะไรเลย

- การจ่ายเงินตอนรับผ้าเข้ายังไม่ได้ใส่ เพราะยังไม่รู้ว่าร้านทำหรือไม่

## สร้างไฟล์ใหม่ยังไง

ไฟล์ทั้งสองสร้างจากสคริปต์ Python ที่ประกาศ node และ waypoint แล้ว generate XML ออกมา
วิธีนี้ทำให้พิกัด DI ตรงกันเสมอ และตรวจความถูกต้องอัตโนมัติได้

ตรวจที่ทำไปแล้ว · XML parse ผ่าน · ไม่มี id ซ้ำ · sequence flow ทุกเส้นมี DI ครบ ·
waypoint ต้นและปลายอยู่บนขอบของ shape จริง (0 ปัญหา)

ถ้าจะแก้แผนภาพ แก้ในเครื่องมือ BPMN ได้เลย ไม่ต้องกลับไปแก้สคริปต์
