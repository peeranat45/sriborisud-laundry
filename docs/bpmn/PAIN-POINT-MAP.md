# แผนที่เชื่อม As-Is → Pain Point → To-Be

เอกสารนี้ตอบคำถามเดียว · **ทุก task ที่หายไปหรือเปลี่ยนไปใน To-Be แก้ pain point ข้อไหน**
และสำคัญไม่แพ้กัน · **pain point ข้อไหนที่ยังไม่ถูกแก้**

---

## ⚠️ อ่านก่อน · ช่องที่เว้นว่างไว้

ช่อง PP ที่เขียนว่า `__` คือข้อที่ผมไม่สามารถยืนยันเลขได้จากรายการ PP1–PP29 ที่คุณเรียงใหม่
ผมเติมเฉพาะเลขที่มั่นใจเท่านั้น และ **จงใจไม่เดาเลขที่เหลือ**
เพราะถ้าเดาผิด แผนที่ทั้งฉบับจะพาคุณไปอ้างผิดในรายงาน

ให้เปิดรายการ PP ของคุณแล้วเติมช่อง `__` ด้วยตัวเอง · คำอธิบายปัญหาในคอลัมน์ที่สองถูกต้องแล้ว
ใช้เป็นคีย์ในการจับคู่ได้เลย

ข้อความ `[PP __]` ที่ฝังอยู่ใน text annotation ของไฟล์ `.bpmn` ก็ต้องเติมแบบเดียวกัน
แก้ได้โดยตรงในโปรแกรม BPMN ไม่ต้องกลับมาแก้สคริปต์

---

## รูปแบบการเปลี่ยนแปลง 5 แบบ

| # | รูปแบบ | ความหมาย |
|---|---|---|
| 1 | **Eliminate** | งานนั้นหายไปเลย |
| 2 | **Automate** | ระบบทำแทน ไม่ต้องใช้คน |
| 3 | **Informate** | คนยังทำเหมือนเดิม แต่เห็นข้อมูลที่เมื่อก่อนมองไม่เห็น |
| 4 | **Add record** | **งานใหม่ที่เพิ่มขึ้นให้พนักงาน** คือต้นทุน ไม่ใช่ประโยชน์ |
| 5 | **Push** | ข้อมูลถูกส่งออกไป แทนที่จะต้องไปตาม |

แบบที่ 2 กับ 3 คือ automate กับ informate ตามแนวคิดของ Zuboff
แบบที่ 4 คือข้อที่รายงานของนักศึกษามักซ่อนไว้

### สองแถวล่างคือแถวที่ต้องพูดถึงในรายงาน

**Add record · 4 จุด** คืองานที่เพิ่มขึ้นจริงให้พนักงาน ไม่มีใครสแกนอะไรเลยในวันนี้
ผ้า 1 ชิ้นถูกสแกนราว 4–6 ครั้งตลอดสาย × ประมาณ 130 ชิ้นต่อวัน
ถ้าสแกนละ 3 วินาที คือราว 100 ชั่วโมงต่อปีที่เพิ่มขึ้น
**เขียนตัวเลขนี้ไว้ในรายงานตรงๆ แล้วเถียงว่าคุ้ม** จะแข็งแรงกว่าการทำเหมือนระบบไม่มีต้นทุน
และสิ่งที่ซื้อมาด้วยต้นทุนนี้คือ `คิดค่าแรง` ที่ตรงกับงานจริง ซึ่งเป็นเหตุผลที่พนักงานจะยอมสแกน

**ไม่เปลี่ยน · 1 จุด** คือการตรวจเงินเข้า · ระบบสร้าง QR ตามยอดจริงได้
แต่ยืนยันว่าเงินเข้าแล้วหรือยังไม่ได้ เพราะไม่มีสิทธิ์เข้าถึง API ธนาคาร
เจ้าของร้านยังต้องเปิดแอปธนาคารดูเอง · เขียนข้อจำกัดนี้ไว้ชัดๆ อย่าปล่อยให้เข้าใจว่าระบบตรวจให้

## pain point ที่ยังไม่มีที่อยู่ในแผนภาพชุดนี้

แผนภาพ 12 ไฟล์ครอบคลุมกระบวนการหลัก แต่ยังไม่มีเส้นทางสำหรับ

| เรื่อง | ติดคำถาม | กระทบไฟล์ไหน |
|---|---|---|
| บิลยกเลิก | **N1** | W1 · W6 ต้องมี path ยกเลิก |
| ผ้าเสียหายหรือสูญหาย | **N2** | W3 To-Be หยุดที่ `รอเจ้าของร้านตัดสินใจ` |
| การแก้ไขบิลหลังออกแล้ว | **N3** | ยังไม่มีในแผนภาพใดเลย |
| ผ้าค้างรับนานที่สุด | **N4** | W5 เกณฑ์การเตือนยังไม่มีตัวเลข |
| จ่ายเงินตอนรับผ้าเข้า | ถามเจ้าของร้าน | W1 ยังไม่มีขั้นตอนชำระเงิน |

**ยังไม่ต้องวาด** การวาดเส้นทางที่ยังไม่รู้ว่าร้านทำอย่างไรจริง คือการแต่งเรื่อง
ไปร้านครั้งเดียวได้คำตอบทั้ง 5 ข้อ แล้วค่อยเติม
